# 交稿檢查表

先跑機器檢查，再做人工檢查。機器擋得住格式與套語，擋不住「內容是不是對的」。

## 第一關：機器檢查

```bash
python3 工具/檢查稿件.py 你的稿件.md
```

會比對 `01-語料統計.md` 的實測門檻並列出：句長、段落、問號密度、你／您、
疑問句小標比例、保留語數量、具體數字、AI 套語命中、公司名命中、結構元件是否齊全。

⚠️ 只代表偏離語料的常態，不一定是錯——短文章的問號密度天生偏高。
❌ 一定要改：AI 套語、公司名、出現「您」。

## 第二關：正確性（保險文章的命脈）

- [ ] 每個「會賠／不賠」的斷言，都有加上條件或保留語？
- [ ] 有沒有任何一句可以被讀者理解成「保證理賠」？
- [ ] 引用的法條有寫到條次？機構名稱正確（金管會 / 保險局 / 金融消費評議中心 / 健保署）？
- [ ] 引用的數字有年份、地區、來源？
- [ ] 文中有沒有寫到商品名、公司名、費率、投保規則？（有就刪，那些會過期）
- [ ] 案例有標明「個案結果不能套用到其他人」？
- [ ] 文章有沒有界定自己的範圍（不能取代什麼）？
- [ ] 更新觸發條件寫進任務書了嗎？（制度一改就要回來修的那種文章）

## 第三關：讀者能不能行動

- [ ] 每個小標的第一到第二句就給了答案？（Answer-first）
- [ ] 隨便挑一段單獨看，主詞、條件、時間都完整，看得懂？
- [ ] 每個步驟都是一個當場做得完的動作（找出／核對／比對），不是「了解」「掌握」？
- [ ] 讀者看完知道下一步做什麼？
- [ ] CTA 有先描述他的處境，再說要準備什麼？（不是只有「歡迎諮詢」）

## 第四關：AI 味的結構檢查（機器測不出來的）

- [ ] 段落長度有長有短，不是每段都四行？
- [ ] 小標句型有變化，不是清一色「XX 的重要性」或全部同一種問句？
- [ ] 有沒有連續三段都用三點排比？
- [ ] 全文至少出現一次「例外」或「但是」？（只有原則沒有例外＝沒有實務經驗）
- [ ] 至少有一個只有你寫得出來的東西：你經手過的爭點、你整理的順序、你踩過的坑？
- [ ] 結尾不是空泛勵志（「希望大家都能擁有完整的保障」）？

## 第五關：SEO 元件（技術面走 `seo` skill，這裡只查內容端）

- [ ] Title 準確說明主題，自然含核心需求，不機械重複關鍵字
- [ ] Meta description 說清楚答案、差異與下一步
- [ ] H1 一眼看出這頁的任務；H2/H3 反映真實層級，不為塞詞亂切
- [ ] 站內連結 3 條以上，錨文字寫目的（「保單健診怎麼做」）不是「點這裡」
- [ ] 這篇在主題群裡的位置寫出來了（母文／子文／系列之一）
- [ ] 圖片 alt 說明在這頁的用途，不是複製標題
- [ ] 文末 Q&A 是寫給人看的；**不要為它加 FAQPage 結構化資料**
      （2026-05-07 起已完全從 Google 搜尋結果移除，加了不會有版位）

## 發布後

- [ ] 記錄發布日與當時的目標關鍵字，兩週後回來看 Search Console 曝光
- [ ] 內容實質更新才改「最後更新日期」，不要為了看起來新而改日期
