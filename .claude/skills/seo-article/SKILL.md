## 第 1 步：確認這篇要解決的搜尋問題

寫任何一句之前，先用一句話回答：

> 有人在 Google 打「{主攻關鍵字}」，他當下卡住的事情是什麼？

答案要具體到能想像那個人。「想了解新生兒保險」不算答案，
「寶寶剛出生，一堆事擠在一起，不知道保險這件事該排第幾」才算。

**這句話會決定開場的前三句。** 前三句沒有講中這件事，整篇就白寫。

---

## 第 2 步：內容紀律（保險內容的四條紅線）

1. **不寫公司名、商品名、費率。** 寫「判斷的方法」，不寫「這張保單多少錢」。
   要寫「實支實付的分項限額要分開看」，不要寫「A 公司限額 30 萬」。
2. **不給保證。** 沒有「一定會賠」「一定能保」。
   把「賠不賠」拆成「決定賠不賠的是這幾件事」。
   保留語（不一定／視情況／依契約為準）在專業型文章中應出現 3 次以上。
3. **數字要能追溯，但不要為了補數字去查。** 引法條寫到條次，引機構寫清楚是
   金管會、健保署還是國健署，引統計要有年份。做不到就不要寫那個數字。
4. **遇到可能過期的制度說法，標記不要改寫。** 在稿子裡標一行
   `<!-- 待確認：此處制度可能已變動 -->`，交給使用者判斷。

## 第 3 步：語氣門檻（實測值，不要憑感覺調）

| 項目 | 標準 |
|---|---|
| 句子長度中位數 | 20 字上下 |
| 單句上限 | 50 字，超過就斷句 |
| 段落 | 1–3 句 |
| 人稱 | 用「你」。**「您」整篇不要超過 1 次**，最好是 0 |
| 疑問句 h2 比例 | 至少 25% |
| AI 腔套語 | 0 |

**禁用詞**：綜上所述／總而言之／值得注意的是／隨著⋯⋯的發展／在當今社會／
不僅⋯⋯而且／扮演著重要的角色／至關重要／眾所周知／本文將帶您／讓我們一起／
深入探討／全面解析／保障您的權益／為您量身打造／一應俱全

**比單字更致命的是結構上的 AI 味**：每段一樣長、每個 h2 同一句型、
凡事三點排比、只有原則沒有例外、沒有任何具體時間或金額、結尾一句空泛勵志。

---

## 第 4 步：標題層級（h1/h2/h3 的硬規則）

- **h1 整頁只有一個**，就是文章標題，**主攻關鍵字要出現在裡面**，全形 30 字以內。
- **h2 是文章骨架**，每個 h2 底下第一到第二句就要給答案（Answer-first），
  不要鋪陳三段才講重點。**至少 25% 的 h2 寫成問句。**
- **h3 只在 h2 底下真的有並列子項時才用**，不要為了層次好看而用。
- **不可跳級**（h2 之後不能直接接 h4）。
- 篇幅對照（語料實測）：
  - 判斷型（該不該、怎麼選）：3,000 字 / 8 個 h2
  - 情境型（怎麼做、流程）：1,500–2,400 字 / 5–6 個 h2
  - 觀念型（是什麼）：2,000 字 / 6 個 h2

```
h2 ...（主體，每個 h2 先給答案再給理由）
h2 ...
h2 ...
[範圍界定] 這篇不能取代什麼（1 段）
```

### 快速答案區為什麼重要

Google 的 AI 功能沒有專屬優化手段，就是把基本 SEO 做好
（見 `google-facts.md` §12：不需要 llms.txt、不需要 chunking、不需要特殊 schema）。
但**一段能被單獨看懂、直接回答問題的文字，是被擷取的前提**。
把它放在 h1 之後、第一個 h2 之前，用 `<div class="quick-answer">` 包起來。

### 目錄怎麼做（2026-09-05 使用者指示：開頭放目錄，不要放「先說結論」）

使用者的原話：「文章開頭不要寫『先講結論』，而是把文章內容寫成目錄讓潛在客戶點擊跳轉。」

**所以 `references/02` 與 `03` 裡的「先說結論」區塊不要再放。** 那兩份寫的是對標語料的常態，
使用者的決定優先。開頭順序固定是：問題情境一段 → 目錄 → 系列定位句 → 範圍界定。

做法：

1. 每個內文 `h2` 加 `id="sec-1"`、`sec-2`⋯⋯依序編號。
   **「延伸閱讀」與 CTA 的 h2 不編號、不進目錄**，那是功能區塊不是內容。
   「常見問題」要進目錄。
2. 目錄放在問題情境之後、第一個 h2 之前：

```html
<nav class="toc" aria-label="文章目錄">
  <h2>這篇文章會談什麼</h2>
  <ol>
    <li><a href="#sec-1">（h2 標題原文）</a></li>
    ...
  </ol>
</nav>
```

3. CSS 要加 `h2[id]{scroll-margin-top:24px}`，不然跳過去標題會被切掉。

**這個改動沒有 SEO 代價，不要再跟使用者說有。** 2026-09-05 查證 Google 官方文件：
Google 從未規範答案或結論要放前面，`ai-optimization-guide` 明講
"You don't need to write in a specific way just for generative AI search."
與 "There's no requirement to break your content into tiny pieces for AI to better understand it."；
`featured-snippets` 對「怎麼讓自己被選上」的回答是 "You can't."
「先說結論」的唯一依據是對標語料中專業型網站 70% 這樣寫，那是同業做法不是搜尋引擎規範。

⚠️ **寫目錄的程式陷阱**：用正則抓 `<h2>` 時，
檔頭註解裡若出現 `<h2>` 這五個字會被當成真標籤，`.*?</h2>` 會吃掉整份檔案。
2026-09-05 實際發生過。作法：只在「▼▼▼ CMS 內文從這裡開始」到「▲▲▲ 結束」之間操作，
並限定同一行、80 字以內的 h2。

### 第 5.5 步：行動呼籲（每篇必備，兩步式）

**每一篇文章都要有 CTA，沒有例外。**

⚠️ 2026-09-05 使用者改過一次。原本是三顆並排按鈕，他的評語：
「CTA 不要一次性全部放上去三個，應該是 1~2 個就好，然後是連貫的。」
**三顆並排是選單，會逼讀者做選擇；要的是一條路。**
另一個問題是按鈕只有名稱沒有好處：「CTA 的部分缺少明確的誘因」。

固定結構，四篇已套用，照抄不要自由發揮：

```html
<div class="cta">
  <p>{這篇讀者當下的處境}</p>
  <p class="benefit">每個家庭的需求不盡相同，需求分析DIY可以讓你不透過業務，完整盤點自己的保險需求，並取得一份客製化的分析報告。<b>拿著這份報告再去問業務，也比較不會被牽著鼻子走。</b></p>
  <div class="cta-actions">
    <a class="primary" href="https://baojiajia.tw/analysis">免費使用需求分析 DIY</a>
  </div>
  <p class="next">取得報告之後，也歡迎你找我們<a href="https://baojiajia.tw/contact">免費諮詢</a>，或直接用 <a href="https://lin.ee/v47HvMr" target="_blank" rel="noopener">LINE</a> 問。</p>
</div>
```

規則：

- **主按鈕只有一顆**，永遠是需求分析 DIY `https://baojiajia.tw/analysis`。
- **第二步寫成句子，不是按鈕。** 用「取得報告之後」把兩件事串成順序。
  聯絡我們與 LINE 是句子裡的文字連結，視覺上是第二層。
- **誘因文案是使用者訂的，逐字照抄，不要自己改寫。**
  它有效是因為直接回應保險客戶最大的恐懼（被業務牽著走），
  也符合網站「沒有推銷壓力」的定位。
- **CTA 不要標題。** 2026-09-05 使用者刪掉四篇的 CTA 標題，評語：「這種句子都是廢話」。
  被刪的是「時間軸看完了，接下來看你自己家的情況」「六個重點看完了，接下來看你家的缺口在哪」
  這一類。**「X 看完了，接下來⋯」是純過場**——讀者剛讀完，不需要有人通知他讀完了，
  而且四篇同一個句型正是結構上的 AI 味。CTA 直接從讀者的處境那一句開始。

- **開場那一句要為這篇寫，而且要有內容。** 判準：這句話刪掉，讀者會不會少知道一件事？
  不會，就是廢話。已用過的（都通過這個判準）：
  「寶寶快出生了，但投保順序還沒整理好？你不用先把所有險種研究完。」
  「不用整份重來。多數情況只要確認兩三個地方，就知道現在這份夠不夠用。」
- **禁止**：「現在不買就來不及」「錯過就沒有了」「限時」。
- 位置：延伸閱讀之後、Q&A 之前。
- CTA 裡的連結**不算**站內連結配額。

### Q&A 區怎麼寫

- 5–6 題，每題答案 2–4 句，**答案第一句就要是答案**。
- 題目直接用真實搜尋問法（從次要關鍵字來），不要自己編漂亮的問題。
- 用 `<h3>` 當問題，不要用 `<strong>`。
- **不要加 FAQPage 結構化資料。** `references/05` 交稿檢查表第五關明訂不加，
  理由是它自 2026-05-07 起已完全從 Google 搜尋結果移除，加了不會有版位。
  Q&A 靠可見文字本身就能被人與 AI 讀到，不需要那段 JSON-LD。

## 第 7 步：HTML 產出規格

檔名：`SEO寫作培訓/文章範本/{slug}.html`

**檔案要是一份可以直接在瀏覽器打開看的完整 HTML**，包含 `<head>`。
但同時要用註解標出「貼進 CMS 的是哪一段」，因為網站的 head 標籤是由
`src/components/SEO.tsx` 依 CMS 欄位產生的。

### head 必備（順序照抄）

```html
<html lang="zh-Hant-TW">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
```

### JSON-LD 必備三塊

一個 `<script type="application/ld+json">`，用 `@graph` 包三個物件：

1. **BlogPosting** — `headline`、`description`、`image`、`datePublished`、`dateModified`、
   `author`、`publisher`（Organization + logo）、`mainEntityOfPage`、`inLanguage: "zh-Hant-TW"`、
   `articleSection`、`isAccessibleForFree: true`
   - `dateModified` **只在真的改了實質內容時才動**。改個年份就更新日期＝自毀訊號。
   - `datePublished` 與 `dateModified` 都要用完整 ISO 8601 含 `+08:00`。
2. **BreadcrumbList** — 首頁 → 知識專區 → 分類 → 本篇（第 4 層 `item` 可省略）
**只有這兩個。不要加第三個。** 特別是 FAQPage，見上方 Q&A 段落。

**不要加的 schema**：`FAQPage`（檢查表明訂不加）、`HowTo`（已移除）、`AggregateRating`（自家評價不符資格）、
`LocalBusiness`（使用者不公開地址電話，且 `backups/contact_info.json` 裡是假資料，
填了違反 Google 結構化資料政策）。也不要放 `address`、`telephone` 這兩個屬性。

### 作者一律掛品牌，不掛個人（2026-09-05 使用者指示）

`author` 與 `publisher` 都固定是 `Organization: 保家佳`。
使用者做品牌經營，**不要建議他改成署名個人的 Person，也不要自己加**。

品牌沒有個人資歷可掛，E-E-A-T 靠這三件事補，寫文章時要做到：

- 文內用「我們」「實務上看到的」寫第一手觀察 —— Experience 品牌也能有
- 發布日與最後更新日**讀者看得見**，不是只寫在 schema 裡
- `author.url` 指向 `https://baojiajia.tw/about`

**禁止**：編造「筆者某某，二十年資歷」這類署名，或虛構資歷與證照。

### Organization 固定值

```json
{ "@type": "Organization", "name": "保家佳",
  "url": "https://baojiajia.tw",
  "logo": { "@type": "ImageObject", "url": "https://baojiajia.tw/hero.png" } }
```

### body 結構

用語意標籤：`<article>`、`<header>`、`<section>`、`<nav>`（麵包屑）、`<footer>`。
文內 `<time datetime="...">` 標出發布日與更新日，**要讓讀者看得到**，不是只寫在 schema 裡。
YMYL 主題上，看得見的日期與作者是信任訊號。
